# 碰头 · PARTY

一个轻量、移动端优先的实时聚会游戏基座。手机就是手柄，房间码就是邀请函；无需注册或下载。

当前版本包含完整基座和七款游戏：**「谁最可能」**、**「存钱罐」**、**「怪兽汽车」**，以及棋牌室的 **「五子棋」**、**「飞行棋」**、**「斗地主」** 与 **「德州扑克」**。

## 已实现

- 六位房间码、二维码、昵称与预置头像；「谁最可能」「存钱罐」支持 3–12 人，「怪兽汽车」「飞行棋」支持 2–4 人，「五子棋」「德州扑克」支持 2–6 人，「斗地主」固定 3 人。
- 棋牌室四款标准桌面游戏：五子棋与斗地主由 Three.js 3D 呈现——五子棋的胡桃木棋盘与玉石棋子（拖动旋转、点按/键盘落子、连五高亮）、斗地主的墨绿呢牌桌与扇形手牌（叫分定庄、炸弹/春天翻倍、键盘或点选出牌）；飞行棋与德州扑克为 2D SVG 渲染、无 WebGL 依赖——飞行棋的 52 格方形环道、四角停机坪与纸飞机（掷 6 起飞追加一掷、己色格跳跃、飞行格跨越、终点反弹），德州扑克的深蓝毛毡俯视牌桌、公共牌/彩池/庄位与行动倒计时（2–6 人、起始 2000 筹码 vs 10/20 盲注、每 6 手盲注翻倍、最小加注线、短全下不重开行动权、边池与零头筹码按国际惯例结算）。
- 桌面游戏同样服务端权威：骰子与洗牌只在服务端发生，手牌与底牌按玩家裁剪视图，超时自动托管（能过则过、面对下注弃牌、斗地主跟牌自动不要），不依赖任何客户端上报。
- 首页游戏货架（带标签分类）选好开局游戏，进房即预选；「谁最可能」私密投票、平票计分；「存钱罐」守护/砸罐、有限锤子、天降事件与随机落幕。
- 「怪兽汽车」提供轮子、车头、车尾、车顶、司机五个槽位，每槽八款零件，共 40 款；模型货架每页四款并可翻页，“惊喜一下”只在本地重组完整草稿，点击出发才提交。车库支持拖动或左右方向键旋转、局部换件与登场动效，装车、倒计时、30 秒森林竞演与结算完整串联，随机名次不受零件影响。
- 每辆车按玩家与头像生成稳定的 `CarIdentity`：独立配色、圆点/条纹/星星/棋盘花纹、轻微车身比例与悬挂相位，并悬挂带头像和编号的旗帜；自己的车辆另有识别光环。身份不读取或消耗赛事随机流。
- 服务端权威规则：不能投自己、不能投旁观者、不能越权推进或修改分数；怪兽汽车只接受合法装车动作，最终名次由服务端计划生成。
- 真实 WebSocket 状态同步；每名玩家只收到自己有权看到的游戏视图。
- 怪兽汽车使用公开、可 JSON 序列化的 `RacePlan` 和任意时刻确定性采样；浏览器另从同一计划生成纯本地 `ShowPlan`，编排六种森林故事、天气、双人社交时刻与导演相机。竞演画面不逐帧广播位置，展示计划也不进入协议或快照。
- 怪兽汽车的 Three.js 面板按需加载，模型、头像旗、森林、固定容量天气/反应粒子、GPU 烟花与音效均为程序化自包含资产；零件缩略图由单个临时烘焙器生成静态 data URL，不为每个选项常驻 canvas。WebGL 不可用或上下文丢失时切换为 DOM 降级视图。
- 完赛后结果卡 5 秒自动收起，也可手动关闭或重新展开；车辆每 20 秒循环绕行、按 2/3/4 人编成不同队形、停稳合影并返场，配合会避让结果卡的稳定相机。以上均为本地展示，不新增服务端阶段或逐帧网络消息。
- 刷新与断网自动重连、多标签页处理、30 秒心跳、65 秒假在线清理。
- 操作幂等与冲突检测、消息 schema 校验、HTTP/WebSocket 限流。
- 房间与操作原子快照；正常重启后恢复会话、票型和分数，怪兽汽车恢复同一赛事计划而不重新随机。再来一局保留各参与者最后提交的 build，同时清空准备状态、旧计划和名次，并由服务端生成新种子。
- 任意游戏结算后，房主可结束本局回到大厅换游戏（`end-game`）；对局中加入的旁观者随之转为参与者。回大厅后重选怪兽汽车是全新一局，build 保留只属于「再来一局」。
- 闲置房间自动过期、安全响应头、Origin 校验、无第三方字体或追踪请求。
- 移动端与桌面端完整界面，深色舞台视觉、动效与减少动效偏好支持。

## 快速开始

要求：Node.js 22+（推荐 24）和 pnpm 10。

```bash
corepack enable
pnpm install
pnpm dev
```

打开 [http://localhost:5173](http://localhost:5173)。Vite 会将 `/api` 和 `/ws` 代理到 3000 端口。

生产模式：

```bash
pnpm --filter @party/web build
pnpm --filter @party/server start
# http://localhost:3000
```

默认快照写入 `./data/party.json`。该文件包含会话恢复令牌，请保护它，不要提交或公开。

## 测试与质量门禁

```bash
pnpm test            # 业务规则 + 真实 HTTP/WebSocket 网络测试
pnpm test:ui         # jsdom 中从用户视角组织的 React 组件测试
pnpm test:e2e        # 本地：多浏览器完整对局 + 怪兽汽车真实 WebGL 验收
pnpm test:e2e:online # 线上：直接验收 party.xiaowenz.com，无需多部手机
pnpm test:coverage   # 覆盖率阈值：语句/函数/行 85%，分支 80%
pnpm typecheck       # 严格 TypeScript 检查（含测试）
pnpm build           # 全部工作区检查 + Web 生产构建
pnpm check:all       # 完整 CI 门禁
```

测试按业务语言组织：

```text
tests/
├── business/   # 玩家、房主、恢复、版本 1 兼容与赛事 RNG golden 回归
├── network/    # 真实端口、多 WebSocket、安全/恢复、保留 build、无逐帧广播
├── ui/         # 可见行为、40 款模型、ShowPlan、分阶段反应、天气与循环合影契约
└── e2e/        # Chromium 多浏览器完整流程、真实 Canvas 与持久状态验收
```

首次运行 E2E 前执行 `pnpm exec playwright install chromium`。线上验收复用本地多浏览器场景，不启动本地服务；可用 `pnpm test:e2e:online -- --headed` 观看自动操作。测试会创建真实房间，断开后由服务端按闲置规则自动过期。jsdom 组件测试不能证明真实 WebGL 渲染；怪兽汽车的 Three.js 画布由真实 Chromium E2E 检查。E2E 只断言可持续观察的阶段、缩略图加载完成、最终名次和再来一局后的已保留选择，不断言某一瞬时倒计时文案、反应姿态、天气粒子或相机位置，详见 [测试规范](docs/TESTING.md)。

## 生产自动部署

生产环境为 <https://party.xiaowenz.com>。release PR 合并到 `main` 后，`deploy-main.yml` 会通过 hk-dev 上的 `hk-build` runner 构建并推送 ACR 镜像，然后更新容器并执行 HTTPS/WSS 冒烟。详见 [hk-dev 生产部署](docs/DEPLOYMENT.md)。

## Docker 部署

```bash
docker build -t the-party .
docker run -p 3000:3000 -v party-data:/data \
  -e PUBLIC_ORIGIN=https://party.example.com \
  the-party
```

或直接使用：

```bash
PUBLIC_ORIGIN=https://party.example.com docker compose up -d
```

公网必须由反向代理或托管平台提供 HTTPS/WSS，并将 `PUBLIC_ORIGIN` 设为浏览器实际访问的源（包括协议和端口，如有）。`/data` 必须挂载持久卷。反向代理场景设置 `TRUST_PROXY=true`，直连时不要开启，避免伪造客户端 IP。

**当前版本是单实例架构。** 不要直接启动多个副本做负载均衡；扩容需要按房间路由或引入共享房间运行时，详见架构文档。

## 分支流程

严格采用：

```text
feat/* ── PR ──> dev ── release/* ── PR ──> main
fix/*  ── PR ──> dev
```

`main` 和 `dev` 均为受保护分支，必须通过 PR 合入，必需审批人数为 0。每次开发都从最新 `dev` 创建 `feat/*` 或 `fix/*`；PR 合并后远端自动删除源分支，本地同步后切回 `dev`。详见 [分支规范](docs/BRANCHING.md)。

## 第一款游戏规则

「谁最可能」每轮展示一道轻松的问题。每名参与者秘密投给一名其他参与者，不能投自己；全员提交或 60 秒超时后揭晓。最高票玩家得 1 分，平票则并列玩家都得 1 分。完成所选轮数后按总分排行，房主可以再开一局。

## 第二款游戏规则

「存钱罐」支持 3–12 人，每轮秘密选择守护或砸罐，砸罐者平分罐中金币，守护者获得安慰币。锤子数量有限，金币雨、烫手罐、盲罐、纸糊罐和警报轮会改变结果；实际落幕轮保密，罐中余币终局平分。

## 第三款游戏规则

「怪兽汽车」支持 2–4 人，每次进行一场森林旅行（`rounds: 1`）。每位参与者从五个槽位各选一款零件，每个槽位有八款选择（共 40 款），也可以使用开局生成的完整默认车辆。货架每页显示四款；“惊喜一下”为每槽从当前 ID 之外本地选一款，只改变草稿。拖动车预览可旋转，也可用左右方向键；换件只替换对应模型并播放 0.45 秒弹跳动效。提交 `build-car` 即准备完成，准备后仍可改装；全员提交或 120 秒组装期限到达后进入 3.2 秒倒计时，未准备玩家使用当前车辆自动出发。随后进行 30 秒竞演并进入结算。房主再来一局时保留所有参与者最后提交的 build，但重新准备并使用新的服务端种子。

赛道包含水坑、木头、阵风和山坡事件。每辆车由公开反应目录解析一项 primary，以及可包含其他零件专属响应和司机/车身回退的多项 secondary；Three.js 在主动作前后分别加入 320ms 预备与最长 420ms 跟随，并叠加各零件独立的次要动作。开赛最初 900ms 的轻微前冲、换件弹跳和零件反应都只改变本地表现，不提供速度或名次优势。赛事种子决定随机完赛顺序、配速和反应提示，更换零件不会改变同种子下的完赛顺序与配速。

倒计时开始时，服务端把可序列化的 `RacePlan` 与时间边界发给所有玩家和旁观者。各浏览器用同一个纯函数按绝对赛事时间采样位置、名次与反应，刷新或服务重启后继续同一计划；服务端只在阶段变化等状态变更时广播，不逐帧发送车辆位置。`standings` 到 `finished` 才填充，但 `plan.finishOrder` 从倒计时起就是公开数据，不属于保密结果。

各浏览器再从 `RacePlan` 与公开玩家头像生成可 JSON 序列化、但不联网也不持久化的 `ShowPlan`。它用独立的具名哈希选择六个故事之一，配置对应天气、天空/暮色与装饰，同时派生每辆车的 `CarIdentity`、不重叠的双人互动和开场/车队/事件/社交/终点相机。天气与车辆姿态可任意时刻重采样；新增这些表现不会消费 `RacePlan` 的 RNG，也不改变既有网络字段。

进入 `finished` 后，浏览器继续按赛后绝对时间采样云朵操场。每 20 秒一轮：保留最初 1.5 秒入场和圆环行驶，5.0–6.4 秒进入按车辆数选择的队形，6.4–9.4 秒完全停稳合影，9.4–11.4 秒返回圆环，随后继续绕行并轮换队形。操场相机按车辆落地后的整体边界构图，在结果卡与合影模式间调整留白；合影期间烟花降低强度。结果卡默认在 5 秒后收起，手动关闭/展开会取消旧计时器。这些只改变本地展示，不增加 `celebrating` 等服务端阶段、不改 standings，也不产生新的网络协议。

`monster-car` 与房间快照继续保持 **版本 1**：身份、故事、社交、镜头和循环合影均不进入权威状态或快照，既有 `RacePlan` 的 RNG 调用顺序与网络消息形状不变。40 个合法零件 ID、反应与资产边界见 [协议文档](docs/PROTOCOL.md) 和 [怪兽汽车资产与反应协议](docs/CAR_ASSETS.md)。

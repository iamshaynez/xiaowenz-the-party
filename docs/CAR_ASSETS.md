# 《这车能开？》素材与演出标准

本文是车辆零件、环境、动画和镜头的内容合同。目标是让新增内容只增加定义与素材，不修改房间、车辆模拟器或其他零件。领域 ID 与行为定义位于 `packages/games/src/can-drive/`，Three.js 视觉工厂位于 `apps/web/src/games/can-drive/rendering/`。

## 1. 坐标、尺寸与所有权

- 使用右手坐标系：`Y` 向上、`+Z` 指向车头、地面为 `Y = 0`。
- 车辆原点位于底盘中心的地面投影；零件原点位于自己的安装接口，不得用任意模型中心代替。
- 统一车身和安装点尺寸。特殊零件可以夸张，但必须声明局部包围盒、最高点和地面接触区域。
- 渲染网格不是碰撞体。碰撞使用简单盒、球、胶囊或平面代理。
- 几何体、材质、纹理和阴影由明确的所有者释放。共享资源由缓存释放，单辆车只释放实例私有资源。
- 所有内容 ID 稳定且只含小写英文、数字与连字符；中文名只用于界面，不作为逻辑键。

## 2. 五类安装接口

| 槽位 | Socket | 必备接口 | 主要行为 |
| --- | --- | --- | --- |
| 司机 | `socket.driver` | 身体根节点、头部节点、表情／手部挂点 | 驾驶、受惊、眩晕、庆祝和环境反应 |
| 运动件 | `socket.motion` | 地面接触区域、运动根节点、旋转或压缩通道 | 滚动、履带、步行、弹跳、滑动、漂浮 |
| 车头 | `socket.front` | 碰撞代理、作用点 | 撞击、推挤、钻入、吸附、吸取等 |
| 车尾 | `socket.rear` | 推进方向、尾迹挂点 | 推进、稳定、泡泡、水、彩带和声音 |
| 车顶 | `socket.roof` | 最高点、展开或旋转节点、特效挂点 | 空气、天气、照明、高度和附件反应 |

每个领域零件必须恰好有一个对应视觉工厂；每个视觉工厂必须返回根节点和标准动画通道。缺少非关键通道时使用通用回退，不允许悄悄丢失整辆车。

## 3. 运动原型

新运动件优先复用以下原型，只调整参数和外观：

- `rolling`：普通轮、巨型轮、方轮。
- `tracked`：履带。
- `stepping`：机械足、鸭掌。
- `bouncing`：弹簧。
- `sliding`：滑雪板。
- `floating`：气球。

连续运动由模拟器输出，不能烘焙成与物理无关的固定位移：车轮旋转、履带相位、脚步、悬挂压缩、车身姿态、推进和悬浮均由时间线驱动。

## 4. 标准动画与回退

零件使用：

- `idle`：待机。
- `activate` / `deactivate`：开始／停止工作。
- `impact`：受到撞击。
- `react`：通用环境反应。
- `open` / `close`：展开／收起。
- `celebrate`：颁奖庆祝。

司机使用 `drive / brace / dizzy / cheer / wave`。

缺少片段时按 `具体反应 → react → idle` 回退；司机庆祝按 `celebrate → cheer → idle`。片段不得移动车辆根节点。镜头、声音和奖项不能依赖某个模型的私有动画名称。

## 5. 环境刺激与能力标签

环境只声明刺激，不导入具体零件 ID：

- 地面：`washboard / mud / water / ice`。
- 天气：`crosswind / rain`。
- 空间：`low_clearance / darkness / soft_obstacle / magnetic_field / jump`。

零件声明能力，例如 `buoyant / bouncy / magnetic / light_source / weather_cover / water_sensitive / sound_maker / plant / detachable / wind_catcher`。

统一响应形式为：

> 环境刺激 + 零件能力 → 运动修正 + 标准动画 + 特效 + 音效 + 语义事件

每个零件至少具有普通行驶反馈和两个环境响应。特定组合彩蛋可以显式增加，但不能替代基础反馈。

## 6. 语义事件与镜头

模拟器与渲染器通过事件协作：

- `part.activate / part.impact / part.open / part.detach`
- `vehicle.airborne / vehicle.land / vehicle.splash / vehicle.collision`
- `driver.react`
- `scene.highlight / show.finish`

事件包含时间、环境、强度与必要的公开参数。高光只记录时间段和镜头提示，颁奖时重新驱动模型，不录制视频。

镜头使用统一提示：`establish / follow / impact / airborne / driver_reaction / landing / award`。同一时刻只播放一个主要特写；物理响应优先于装饰粒子，低画质只能减少表现，不能改变结果或奖项。

## 7. 黏土视觉预算

- 使用暖色、圆角、哑光和柔光，禁止为了单件素材引入写实时装或独立画风。
- 优先共享圆角几何、球体、基础司机身体和共享材质。
- 移动端只保留当前活动车辆的高细节模型，队列使用 DOM 卡片。
- 移动 DPR 上限 1.5，动画目标 30fps；低档减少实时阴影和粒子。
- 素材不得发起第三方网络请求，不依赖远程贴图、字体、解码器或追踪服务。

## 8. 新增内容验收

新增零件时必须同时完成：

1. 领域定义：ID、名称、槽位、行为、标签和环境响应。
2. 视觉工厂：安装点、动画通道、包围盒与特效挂点。
3. 默认车装配测试和至少两个环境响应测试。
4. JSON 快照恢复与固定种子展示测试。
5. 代表帧检查：零件可辨识、不遮挡司机、不破坏镜头。
6. 资源释放与低画质检查。

新增环境时必须提供时长、入出场位置、地面参数、刺激、镜头和结束条件，并用全部零件做无画面冒烟测试。新增奖项只能读取语义统计，不读取模型名称；必须有触发条件、标题、奖章、庆祝模板和回退。

不兼容的 ID、行为、ShowPlan 或恢复结构变化必须提升游戏 `version`，不得静默误载旧房间快照。

# TDD 与测试规范

## 原则

功能采用 RED → GREEN → REFACTOR：

1. 先从玩家、房主或攻击者的可见行为写失败测试。
2. 运行并确认失败原因是没有实现，而不是测试环境错误。
3. 写最小实现使场景通过。
4. 在测试保护下重构，保持严格类型检查。

测试不依据类名和私有方法堆砌，而依据业务场景命名。例如“全员提交后立即揭晓”“重复操作重发保持幂等”“服务重启后恢复票型”。

## 分层

- **business**：纯领域规则，快速覆盖所有阶段、平票、越权、非法输入和快照兼容。
- **network**：启动真实 Fastify 端口，通过 HTTP 和 `ws` 客户端验证鉴权、广播、私密视图、心跳、限流、多标签页、超时和重启。
- **ui**：React Testing Library 从角色、标签、按钮和可见文本验证用户行为；网络适配器可替换，但不 mock 被测组件。
- **e2e**：Playwright 启动生产服务，以隔离浏览器上下文完成多玩家对局、手机刷新恢复和再来一局；「这车能开？」另覆盖双人完整展示与固定三维代表帧。

## 门禁

`pnpm check:all` 依次执行：

1. 业务/E2E 以及所有工作区的 TypeScript 检查。
2. 业务与网络测试及覆盖率阈值。
3. UI 行为测试。
4. 生产构建。
5. 真实浏览器 E2E。

覆盖率全局最低：语句 85%、函数 85%、分支 80%、行 85%。不得为了让 CI 变绿而降低阈值或删除有意义的断言。

## 线上多人验收

一个人也可以验证生产环境，无需多部手机：

```bash
pnpm test:e2e:online
# 观看三个虚拟玩家的实际操作
pnpm test:e2e:online -- --headed
```

该命令通过 `PARTY_BASE_URL=https://party.xiaowenz.com` 禁用本地 `webServer`，让现有三浏览器场景直接访问生产环境。也可将 `PARTY_BASE_URL` 指向其他已部署环境。

线上测试使用真实房间和真实 WebSocket；测试结束后浏览器断开，房间按闲置 TTL 自动过期。失败时保留 trace 与截图，不得在公开 issue 中上传含私人昵称或会话信息的调试材料。

## 新增测试的要求

- 一个场景只验证一个业务承诺，但允许包含完整用户流程。
- 网络测试不能使用 mock WebSocket 替代真实连接。
- 对私密信息不仅检查 UI，还检查实际网络载荷。
- 每个异步测试必须有超时和可靠清理，避免悬挂端口。
- 不依赖固定房间码、随机题目或真实等待 60 秒；通过注入时钟/随机数控制边界。
- 失败截图、trace 和覆盖率文件不提交 Git。

## 三维内容与视觉测试

- 领域 ShowPlan 使用注入随机数和固定时间测试，不通过真实等待验证车辆或颁奖。
- 全部零件工厂与环境必须在无 WebGL context 的测试中实例化，检查安装点、动画引用、有限数值和资源释放。
- React UI 测试只 mock Three 适配器，不用 jsdom 冒充真实渲染。
- 浏览器代表帧固定种子、相机、DPR、画质与时间，覆盖组装、环境响应、腾空、颁奖和手机队列；动态 RAF 不能直接作为不稳定的像素基线。
- 真实浏览器验收补充检查材质、遮挡、镜头、点击区域和性能；DOM 可见不代表 WebGL 已正确显示。
- 素材接口、环境刺激与新增内容验收见 `docs/CAR_ASSETS.md`。
